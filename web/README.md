# CinePro Web

Browser app with email/password signup, login, optional Google sign-in, and PostgreSQL account storage. Raspberry Pi installers, native playback, NAS browsing, phone pairing, and TV remote controls are excluded.

## Start with Docker

Install and start Docker Desktop (or Docker Engine with Compose). From this directory:

```sh
node scripts/setup-env.mjs
docker compose up --build -d
```

Open **http://localhost:5180/signup** to create an account, or **http://localhost:5180/login** to sign in. No Google credentials are needed for email/password accounts. Public registration is now closed by default; existing accounts can log in. The setup script creates `.env` and fills missing database and internal streaming credentials with random values, preserving existing configured values.

The Compose stack runs the app, PostgreSQL, and the internal CinePro streaming provider service in separate containers. PostgreSQL has a persistent named volume and no exposed host port. The app listens on localhost port 5180. Database migrations run automatically before the app becomes ready. Compose waits for the database health check before starting the app, using Docker's [documented startup dependency behavior](https://docs.docker.com/compose/how-tos/startup-order/).

```sh
docker compose ps
docker compose logs --tail=100 app
docker compose stop
docker compose up -d
```

Accounts and sessions survive app restarts and ordinary `docker compose down` / `up`. **`docker compose down -v` deletes the database volume and accounts.** Back up PostgreSQL before removing volumes or upgrading its major version.

In WSL without Docker integration, use `docker.exe compose` in place of `docker compose` while Docker Desktop is running.

## Authentication

Signup is closed (`SIGNUP_ENABLED=false`). Existing password and Google accounts can log in. An operator can temporarily set `SIGNUP_ENABLED=true` and recreate the app to allow new accounts with a name, email, and password of 12–128 characters. Passwords are salted and hashed with scrypt. Session cookies are HttpOnly and SameSite=Lax; session tokens are stored as hashes in PostgreSQL and expire after 12 hours. Logout revokes the session server-side.

Google sign-in remains optional. Follow the [Google OpenID Connect setup guide](https://developers.google.com/identity/openid-connect/openid-connect) to create a Web application OAuth client. Configure the consent screen and any required test users. Register this exact redirect URI:

```
http://localhost:5180/auth/callback
```

Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` in `.env`, then run `docker compose up -d` to recreate the app with the new configuration. `GOOGLE_ALLOWED_EMAILS`, when populated, restricts Google login to that comma-separated list; leaving it empty adds no email allowlist restriction. New Google account creation is still denied while `SIGNUP_ENABLED=false`.

A Google identity is verified and matched by its provider subject. Existing password accounts are not automatically linked merely because an email matches; use the original sign-in method. Email delivery, password reset, and email-address verification for password accounts are not configured in this version.

## Configuration and deployment

- `WEB_PORT`: host port for the app (default 5180).
- `APP_ORIGIN`: exact browser origin without a trailing slash. Use the same hostname consistently; localhost and 127.0.0.1 are different origins.
- `POSTGRES_PASSWORD`: database credential. The setup script generates a URL-safe hexadecimal password; use URL-safe characters if replacing it because Compose includes it in `DATABASE_URL`.
- `DATABASE_URL`: PostgreSQL connection string when running outside Docker. Compose supplies its own internal connection string.
- `TMDB_READ_ACCESS_TOKEN`: optional server-side TMDB catalog token.
- `CINEPRO_API_URL`: defaults to `http://core:3030`, the bundled internal provider service. Set it only to override that service.
- `CINEPRO_API_TOKEN`: random shared credential used between the web app and core; generated by the setup script.
- `SIGNUP_ENABLED`: defaults to false; controls password and Google registration.

No credentials are included in the browser bundle or Docker image. `.env` is excluded from Git and Docker build contexts. Keep it private. Existing PostgreSQL volumes retain their original database password; changing `.env` alone does not rotate a password in an initialized database.

For public hosting, set `APP_ORIGIN` to your HTTPS origin and register the matching Google callback. Put the app behind a trusted HTTPS reverse proxy; cookies use Secure on HTTPS. Plain HTTP is supported only for loopback development origins. Set `TRUST_PROXY=true` only when requests pass through a trusted proxy. The supplied Compose port mapping is bound to the local host; adjust it deliberately for your deployment.

The database stores accounts, sessions, and OAuth transactions. Browser watch history and preferences remain local to that browser. Catalog and media routes require authentication. The core includes the customized provider implementations from the original installation, including embedded and direct streams. A TMDB token is required for catalog and source resolution. The core is not published on a host port; browsers use authenticated web routes. External provider availability varies; select another source if one is unavailable.

## Local development and checks

Requires Node.js 22.12 or newer and a running PostgreSQL database. Set a reachable `DATABASE_URL` and matching `APP_ORIGIN` / `PORT` in `.env` before starting outside Docker:

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
```

Run the browser signup/login checks against the running app using the repository's Playwright installation:

```sh
WEB_TEST_URL=http://localhost:5180 node tests/login-ui.mjs
```

Check account and session persistence across an actual app-container restart:

```sh
node tests/docker-auth.mjs
```

In WSL set `DOCKER_COMMAND=docker.exe` for that command. It restarts only this stack's app service.

To run the PostgreSQL integration test directly from the host, use `docker compose -f compose.yaml -f compose.test.yaml up -d db` to temporarily publish PostgreSQL on localhost:55432, set `TEST_DATABASE_URL` to that connection using your private database password, then run `npm test`. Return to `docker compose up -d` afterward to remove that test port.

The signup browser tests require SIGNUP_ENABLED=true and create uniquely named test accounts. For closed-registration deployments run `WEB_TEST_URL=http://localhost:5180 node tests/closed-signup-ui.mjs`. Authentication unit tests use an explicit test store and mocked Google verification; PostgreSQL integration checks validate the real persistence layer. A real Google redirect additionally needs your OAuth credentials.

### Reverse proxy template

`deploy/cinema.caddy` reads `CINEMA_HOST` from the Caddy process environment
(default: `localhost`). Set it to your own hostname in the server's private
service configuration and keep `APP_ORIGIN` consistent with that HTTPS origin.
An existing deployment should preserve its current hostname when adopting this
template. No deployed proxy or application configuration is changed by checkout.
